# 08 · Решения и уроки

## Ключевые решения
| Решение | Почему |
|---|---|
| Дом и объявление — разные сущности | Дом живёт годами, объявления уходят; история по адресу не теряется |
| Три кошелька денег вместо «стоимости в месяц с мебелью» | Возражение пользователя: мебель частично возвращается; иначе завышаем цену жилья |
| Три отдельных балла (fairness / fit / ручной), не один | Это ответы на разные вопросы; усреднение уничтожает смысл |
| `field_sources` у каждого поля, ≥ 2 источника | Источники противоречат (Danube Flats: 150 vs 180 м, сдача 2023 vs 2025); ошибка с паркингом Grünblick |
| Светится сам дом, без булавок (как ЛУН) | Требование пользователя; своя «оболочка» на ~1 м шире стен, т.к. Mapbox хранит квартал одним объектом |
| Статический сайт + Supabase, доступ двоим | Бесплатно, безопасно (RLS), адреса работ — личные данные |
| Сборщик в edge-функциях, запуск из pg_cron | Сайты недоступны из браузера/контейнера ассистента, но доступны из Supabase |
| Фото и тексты — только ссылки | Чужой копирайт |
| Режим покупки заложен в схему с первого дня | Проект может вырасти в продукт |
| Аддитивные миграции | Деструктивные требуют подтверждения и рискованны |

## Ошибки и что из них вынесли
1. **Не тот аккаунт Supabase** (подключён СЕНАТ) — 40 минут. Решение: кастомный MCP по URL с project_ref → доступ ровно к одному проекту. Правило: всё только в личном аккаунте.
2. **Нелатинский символ в имени колонки** (`betriebskosten_月`) — исправлено отдельной миграцией.
3. **Цвет `#000a`** в стиле Mapbox — после него не добавлялся ни один слой. Только rgba().
4. **Линии транспорта двоились** (туда/обратно) → таблица v2, одно направление.
5. **Пользователь не поверил 43–45 мин** до работы. Проверка: данные верны, но медленный шаг и лишние варианты с прогулкой → `changeSpeed=fast`, фильтр 15+ мин пешком. Урок: сверять с реальным опытом пользователя.
6. **Шум «только у аэропорта»** — на малом масштабе WMS рисует линии вместо зон → тайлы 1024 px.
7. **Grünblick без паркинга** — неверно; пользователь поправил. Перепроверено по 2 источникам → правило ≥ 2 источников.
8. **«Willhaben закрыт для серверов»** — неверное предположение; на деле работает из Supabase. Урок: проверять, а не предполагать.
9. **ImmoScout парсился в 0** — после JSON-объекта шёл JS → вырезание по балансу скобок.
10. **«Grünblick» — обычное слово** в заголовках → ложные привязки → матчинг по названию только ≤ 350 м.
11. **Дежурные аптеки: все 346 «дежурные»** → фильтр по «Bereitschaft von» → ~30.
12. **SQL-функция с http таймаутила и откатывалась** → тяжёлые загрузки перенесены в edge-функции.
13. **Лента показывала не всё**: лимит 5 000 / max-rows PostgREST 1 000 при 5 159 объявлениях → постраничная загрузка по 1 000.
14. **Миграция отклонена из-за таймаута подтверждения** → сообщили пользователю, повторили после подтверждения.
15. **Встроенный браузер на компьютере часто недоступен** → UI проверялся без входа; важно просить пользователя проверить вживую.

## Принципы работы (договорённости с пользователем)
- Ответы по-русски. Перед каждым этапом — какая модель Claude используется. Отчитываться о прогрессе.
- Каждое важное поле дома — ≥ 2 источника, источники в `field_sources`.
- Всё документировать в MD (этот каталог + Project + компьютер), потому что контекст чата может обнулиться.
- Не обходить защиту GitHub от утечки секретов. Временные политики импорта закрывать сразу.
